# 기록 (세션 흐름 5/5)

**핵심은 두 가지다(사용자, 2026-10-14).**
1. 개발 중 알게 된 것을 `aidlc-docs/lessons.md`에 남긴다.
2. **그것 때문에 사이클 자체가 바뀌어야 하면 스킬을 고친다.** lessons는 "알아 둘 것", 스킬은 "다음에 그대로 할 것"이다. 다음 세션이 lessons를 읽고 기억해 내기를 기대하지 말고, 할 일이 바뀌었으면 스킬에 넣는다.

## 스킬을 고쳐야 하는 경우

이번 세션을 돌아보고 하나라도 해당하면 해당 `.claude/skills/cycle-*/SKILL.md`(또는 그 폴더의 스크립트)를 고친다.

| 이번 세션에서 | 고칠 스킬 |
|---|---|
| 스킬의 명령이 틀렸거나 경로·인자가 바뀜 | 그 단계 스킬 |
| 스킬에 없는 단계를 손으로 했고 다음에도 해야 함(예: 큰길 폭을 위성으로 확인) | `cycle-build` 또는 `cycle-verify`에 단계 추가 |
| 검증에서 새 종류의 문제를 찾음(예: 새 건물 유형, 땅에 묻힌 부품) | `cycle-verify`의 확인 목록에 추가(가능하면 자동 확인으로) |
| 인지 단계에서 빠뜨려 시간이 든 정보 | `cycle-recognize`의 읽을 목록에 추가 |
| 기록·커밋 방식이 바뀜 | `cycle-record` |
| 보조 스크립트를 고치거나 새로 만듦 | `src/`(테스트 포함)와 스킬의 명령 |

고칠 때 규칙
- 스킬은 짧게. 이유와 사연은 lessons에, 스킬에는 "무엇을 어떻게"만.
- lessons 항목이 스킬로 옮겨져 다시 겪을 일이 없어지면 lessons에는 한 줄로 줄이고 "→ cycle-xxx에 반영"이라고 적는다.
- 스킬을 고쳤으면 audit에 무엇을 왜 고쳤는지 남긴다.
- 고칠 필요가 없었으면 보고에 "스킬 변경 없음"이라고 쓴다.

무엇을 어디에 쓰는지 섞지 않는다.

| 무엇 | 어디 | 규칙 |
|---|---|---|
| 사용자가 정한 것(결정) | `CLAUDE.md` "결정 사항" | 한 줄, 날짜, "사용자 결정" |
| 지금 상태와 다음 할 일 | `CLAUDE.md` "현재 상태", "다음 할 일" | 낡은 줄은 고치거나 지운다 |
| 사용자 입력과 그에 대한 작업 | `aidlc-docs/audit.md` | **추가만**(덮어쓰지 않음). 형식은 아래 |
| **개발 중 알게 된 것** | `aidlc-docs/lessons.md` | 아래 기준 |
| **사이클이 바뀌어야 하는 것** | `.claude/skills/cycle-*` | 위 "스킬을 고쳐야 하는 경우" |
| 유닛 진행 | `aidlc-docs/aidlc-state.md` | Next Stage와 유닛 줄 |
| 성능 측정 | `aidlc-docs/construction/build-and-test/performance-test-instructions.md` | 날짜, 칸, 위치, 수치 |

## lessons.md 쓰는 기준

- 코드나 문서만 봐서는 모르는 것, 다음에 다시 겪으면 시간이 드는 것만.
- 형식: `- (<날짜>, <칸 또는 범위>) <무엇을 겪었나>. <대처>.` 알맞은 절(Studio·MCP / 생성 규칙 / 데이터·판단 / 작업 방식) 아래.
- 규칙으로 고쳐서 다시는 안 생기는 것은 짧게 남기거나(왜 그 규칙이 있는지) 지운다. 해결되어 필요 없는 항목은 지운다.
- 개인 정보·비밀값 금지.

## audit.md 형식

```
## <제목>
**Timestamp**: <date -u +%Y-%m-%dT%H:%M:%SZ>
**User Request**: (사용자 말 그대로, 필요하면 인용)
**AI Response**: (한 일, 숫자, 커밋)
**Context**: <단계>

---
```

## 커밋

1. `git status --short`로 바뀐 파일을 보고 **내가 바꾼 파일만** `git add <파일...>`. `git add -A`, `git add .`, `git stash` 쓰지 않는다. 내 것이 아닌 변경이 있으면 사용자에게 알린다.
2. 커밋 메시지는 영어 한 줄 요약 + 필요하면 본문, 끝에 시스템이 정한 Co-Authored-By 줄.
3. `git push`.

## 세션을 마칠 때

- 진행 지도: `uv run src/progress.py` → `data/compare/bucheon-progress.png`(부천 752칸의 상태: 완성·판단 끝·수집만), 사용자에게 보낸다.

- 메모리의 `cell-<칸>-session.md`: 칸이 끝났으면 지우고 색인 줄도 지운다. 중간에 멈추면 "진행" 마지막 줄을 다음 할 일로 고쳐 둔다.
- Studio: 저장 여부를 사용자에게 알린다(저장은 사용자 몫). 로컬 서버를 내렸는지, 카메라를 `Fixed`로 되돌렸는지, `HttpEnabled`가 `false`인지.
- 사용자에게 짧게: 끝낸 것, 새 lessons, 고친 스킬(또는 "스킬 변경 없음"), 커밋, 다음 세션이 할 일, 사용자 몫.
