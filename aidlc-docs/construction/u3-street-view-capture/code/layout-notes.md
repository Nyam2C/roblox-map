## 정면 방향 (BR-4.1과 다른 점)

설계는 "파노라마의 heading이 앞면의 방향"이라고 가정했다. 실험에서 **ID로 조회한 `heading`은 앞면 방향에서 180° 어긋나 있었다**(3장 모두, 오차 0.37° 이내).

| 파노라마 | 근처 조회 | ID 조회 | 차이 |
|---|---|---|---|
| 골든타워 근처 | 189.82° | 9.82° | 180.00° |
| 심원고 앞 | 126.77° | 306.76° | 179.99° |
| 로얄프라자 근처 | 271.17° | 90.80° | 180.37° |

확인 방법: 파노라마 안 건물 외곽선(DB)을 두 가정으로 큐브 맵에 겹쳐 그렸다. 근처 조회 값을 쓰면 외곽선이 실제 건물에 맞고(심원고 3장 중 학교 건물이 오른쪽에서 맞음, 로얄프라자 상가와 벽돌 건물이 맞음), ID 조회 값을 쓰면 반대편의 다른 건물에 겹친다. 골든타워 간판도 DB 위치와 맞는 쪽이 근처 조회 값이다.

- 이웃 목록에는 방향이 없고, 후보의 메타데이터는 ID 조회(`find_panorama_by_id`)로만 얻는다. 그래서 어댑터는 **ID 조회 값에 180°를 더해** `heading_deg`로 돌려준다.
- 이 보정은 ID 조회가 3D 파노라마(`panorama_type` 15, 모두 `has_equirect` 참)로 응답한 경우에서만 확인했다. 어댑터는 그 경우만 쓰고 그 밖은 쓸 수 없는 후보로 건너뛴다(추측하지 않는다). 몇 장이 건너뛰어지는지는 Build and Test에서 센다.
- 근처 조회와 ID 조회의 `panorama_type`도 달랐다(3 대 15). 라이브러리 문서가 말한 "ID 조회는 3D에서 틀린 값을 준다"는 경우로 보인다.

## 라이브러리 동작 (어댑터 설계에 영향)

- `find_panorama(lat, lon, neighbors, historical, session)`과 `find_panorama_by_id(id, neighbors=False, historical=False, session)`만 `requests` 세션을 받는다. `is_latest`, `date`, `max_zoom`(4)은 `historical=False`인 ID 조회에서도 온다. 호출 하나로 끝난다.
- 라이브러리의 `get_json`, `get_image`는 **시간 제한도 상태 코드 검사도 하지 않는다**. 403/429 안내문이 오면 JSON 해석 오류로 나온다. 어댑터가 `requests.Session`을 직접 만들어 시간 제한과 `raise_for_status`를 건다.
- `get_panorama(pano, zoom=1, stitching_method=ROW)`는 면마다 `aiohttp`로 4개 타일을 받는다(세션을 받지 않음). 4xx는 바로 `ClientResponseError`, 5xx는 즉시 4번 되풀이한 뒤 같은 오류다. 이 경로의 오류는 `aiohttp.ClientResponseError`(상태 코드), `asyncio.TimeoutError`, `aiohttp.ClientError`, PIL 오류로 분류한다.
- zoom 1은 `max_zoom`을 모르는 `NaverPanorama(id, lat, lon)`로도 받을 수 있다.

## 건물 방향 크롭 확인 (단계 3, `projection.render_crop`)

정면 = ID 조회 heading + 180°로 건물 4개의 크롭(1024×768)을 만들어 눈으로 봤다. 장당 약 0.13초.

| 건물 | 거리 | yaw | 각도 범위 | 시야각 | 위쪽 각도 | 결과 |
|---|---|---|---|---|---|---|
| 심원고등학교 | 45 m | 77° | 118° | 100° | 10° | 학교 건물이 보인다. 이음새와 왜곡 없음 |
| 골든타워 | 21 m | 97° | 118° | 100° | 35° | "골든타워" 간판 건물이 가운데에 온다 |
| 로얄프라자 | 26 m | −85° | 140° | 100° | 20° | 상가 건물 쪽을 향한다 |
| 번호 없는 8층 건물(12403717) | 20 m | −95° | 126° | 100° | 32° | 반대편(동쪽) 건물을 향한다 |

- 가까운 큰 건물은 각도 범위가 100°를 넘어서 시야각이 상한(100°)에 걸리므로 건물 전체가 한 장에 안 들어온다(BR-4.2 그대로). 같은 건물에 방위각이 60° 이상 다른 파노라마를 최대 3장 쓰는 설계(BR-2.4)가 이를 보완한다. 실제 비율은 Build and Test에서 센다.
- 나무와 차량이 건물을 가리는 일이 흔하다. 층수·외관 판단(U4)이 이를 감안해야 한다.
