# U3 거리뷰 캡처 — NFR Requirements

근거: U3 NFR Requirements 계획서 답변 Q1~Q4(A A B A), 기본값 N-U3-1~N-U3-10, U3 Functional Design, U1의 NFR 결정(이어서 적용).
실행 환경은 U1과 같다(사용자 Mac, `uv run`, SQLite). U3에는 비밀값이 없다.

## 1. 확장성
- **U3-NFR-S1** 심원고 3칸이 목표다. 건물과 파노라마 모두 칸 단위로 처리하고, 상한에 닿으면 멈춰서 여러 번에 나눠 돌려도 결과가 같다(BR-6.1).
- **U3-NFR-S2** 한 파노라마는 여러 건물이 공유하므로 칸이 늘어도 이미 받은 파노라마는 다시 받지 않는다(BR-3.1).

## 2. 성능
- **U3-NFR-P1** 새 파노라마 100장(실행당 상한)을 받는 데 10분 이내를 목표로 한다. 시험에서 장당 내려받기가 약 0.8초였고 호출 간격이 1초이므로 약 3~4분이 예상이다. 크롭 생성은 장당 1초 이내를 목표로 한다.
- **U3-NFR-P2** 메모리: 파노라마 한 장은 압축을 풀면 약 19 MB다. 한 번에 한 장씩 처리하고 쌓아 두지 않는다.
- **U3-NFR-P3** 호출 간격 1초(설정값)를 지킨다. 간격을 더 줄이지 않는다.

## 3. 가용성과 복구
- **U3-NFR-A1** 복구 목표는 RTO/RPO 수 시간(요구사항).
- **U3-NFR-A2** 사진(`captures/`)은 백업하지 않는다(N-U3-8). 다시 받을 수 있지만, 네이버가 그 사이 새로 촬영하면 같은 사진이 아닐 수 있다. 촬영일을 `captures`와 `meta.json`에 기록해서 어느 시점의 사진으로 판단했는지 알 수 있게 한다. `captures`, `building_views` 테이블은 U1의 DB 백업에 들어간다.
- **U3-NFR-A3 복구 런북 추가** (U1 런북 R-1~R-6에 이어서):
  - **R-7 파노라마나 크롭이 사라졌다**: 같은 칸으로 `capture.py`를 다시 실행하면 DB의 기록과 파일을 비교해 없는 것만 다시 받고 다시 만든다. 처음부터 다시 하려면 `--replan`.
  - **R-8 차단 신호로 멈췄다**: 실행 기록의 `blocked` 이유를 확인하고 시간을 둔 뒤 다시 실행한다. 다른 방식으로 바꿔 계속하지 않는다. 계속 막히면 사용자와 방법을 다시 정한다.
  - **R-9 `streetlevel`이 기술적으로 고장 났다**(설치 실패, 응답 해석 실패): 어댑터 한 곳이 영향을 받는다. 대체(Playwright)는 새 작업으로 시작한다(기능 설계 Q6=A).

## 4. 보안
- **U3-NFR-SEC1 비밀값** 키나 로그인 정보를 쓰지 않는다. `captures/`는 git에서 제외한다(이미 `.gitignore`에 있다). 사진은 이 Mac 밖으로 보내지 않는다. 사람 얼굴과 번호판이 찍힐 수 있다.
- **U3-NFR-SEC2 공급망(SECURITY-10)** `streetlevel`과 전이 의존성 20개를 모두 정확한 버전으로 고정한다(Q2=A, 총 21개). 무거운 패키지는 `exclude-dependencies`로 뺀다(Q1=A). CI가 줄인 묶음의 `pip-audit`를 돌린다(Q3=B). 이 라이브러리는 네이버가 공개하지 않은 내부 통신을 다루는 서드파티 코드(MIT)라서, 버전이 바뀌면 동작을 다시 확인한다.
- **U3-NFR-SEC3 이미지 검증** 외부에서 받은 이미지는 쓰기 전에 검증한다: 형식이 이미지인지, 크기가 기대(zoom 1은 가로가 세로의 6배, 높이 1024 근처)인지. `Pillow`의 큰 이미지 방지 한도(`MAX_IMAGE_PIXELS`)는 기본값을 끄지 않고 명시적으로 설정한다. 어긋나면 그 파노라마를 실패로 센다(BR-5.4, 3.5).
- **U3-NFR-SEC4 전송 보안** 네이버 통신은 라이브러리의 HTTPS 기본 설정(인증서 검증)을 끄지 않는다. 우리가 만드는 코드가 따로 HTTP 호출을 하지는 않는다.
- **U3-NFR-SEC5 오류 처리와 차단** 오류를 "차단"(403, 429, 응답 형식 이상)과 "일시 오류"(시간 초과)로 나눈다. 차단 신호는 우회하지 않고 즉시 멈춘다(fail closed). 일시 오류만 재시도한다. 최상위 오류 처리는 U1의 `run_cli`를 쓴다.
- **U3-NFR-SEC6 `pyexiv2` 빈 모듈** `streetlevel`이 EXIF를 쓸 때만 쓰는 모듈이 설치되지 않아서, 어댑터가 불러오기 전에 빈 모듈을 끼워 넣는다. 이 우회는 어댑터 한 곳에만 있고 이유를 주석으로 남긴다. 이미지에 EXIF를 쓰지 않는다(D-U3-6). 이 라이브러리 버전이 바뀌면 이 가정이 깨질 수 있어 버전을 고정한다.

## 5. 신뢰성
- **U3-NFR-R1** 일시 오류는 설정된 대기(10초, 30초, 60초)로 재시도한다(BR-5.1). 차단 신호와 연속 3번 실패는 멈춘다(BR-5.2).
- **U3-NFR-R2** 파일은 임시 이름으로 저장한 뒤 이름을 바꿔 완성한다. 반쯤 저장된 파일을 완료로 기록하지 않는다(BR-3.5).
- **U3-NFR-R3** 건물, 파노라마, 크롭 하나의 실패가 다른 것의 처리를 막지 않는다(BR-5.5). 건물 단위로 DB에 저장한다.
- **U3-NFR-R4** 모든 실행은 `collection_runs`에 시작, 종료, 상태, 건수(조회한 건물, 찾은 파노라마, 새로 받은 수, 건너뛴 수, 크롭 수, 사진 없는 건물, 실패 수, 저장된 바이트 수), 멈춘 이유를 기록한다. 로그는 U1과 같은 JSON 파일과 콘솔 요약이다.

## 6. 유지보수성과 테스트
- **U3-NFR-M1 테스트 도구** U1과 같다(`pytest` + `Hypothesis`, 실패 시 시드 출력, CI에서 시드 고정).
- **U3-NFR-M2 테스트 범위** 속성 P3-1~P3-8을 속성 기반 테스트로 만든다. 큐브 맵 투영(P3-5)은 면마다 색이 다른 합성 이미지로 확인한다. 어댑터는 가짜로 바꿔 쓰고(N-U3-1), 네이버를 실제로 부르는 시험은 Build and Test에서 수동으로만 한다.
- **U3-NFR-M3 모듈 분리** 네이버와의 통신은 `src/panorama_source.py`(어댑터), 투영과 방향 계산은 `src/projection.py`(순수), 흐름은 `src/capture.py`로 나눈다.
- **U3-NFR-M4 CI 확장(Q3=B)** CI는 기존 `pytest`와 `pip-audit`에 더해 ①줄인 21개 묶음을 `capture.py`의 인라인 의존성으로 설치해 `import`만 확인하는 자체 점검(`capture.py --selftest`, 네트워크 호출 없음), ②그 묶음의 `pip-audit`를 돌린다. CI에서 네이버를 호출하지 않는다.
- **U3-NFR-M5 버전 일치 검사 확장** `tests/test_versions.py`가 `capture.py`의 인라인 고정 21개가 모두 `==`인지, `tests/requirements.txt`와 겹치는 패키지(`numpy`, `pillow`)의 버전이 같은지, `exclude-dependencies` 설정이 들어 있는지 확인한다.

## 7. 사용성
- **U3-NFR-U1** 명령줄뿐이다. 진행 상황(건물 N/M, 새로 받은 파노라마 N/100, 크롭 수, 사진 없는 건물 수)과 멈춘 이유가 콘솔에 한눈에 보이게 한다.

## 8. 외부 연동과 저장
- **U3-NFR-X1** 네이버 거리뷰(`streetlevel` 경유): 좌표로 파노라마 조회, ID로 메타데이터 조회, 이미지 내려받기. 요청 제한은 알려지지 않았다. 호출 간격 1초와 상한 100장으로 시작하고 실제 실행에서 본다.
- **U3-NFR-X2 저장 공간(Q4=A)** 한도는 두지 않는다. 첫 칸을 받은 뒤 `captures/`의 실제 크기와 장수를 재서 Build and Test에서 보고한다. 실행 기록에 저장된 바이트 수를 남겨서 크기를 추적한다.

| 규칙 | 상태 | 근거 |
|---|---|---|
| SECURITY-01 | 전송 중: 준수(라이브러리 HTTPS 기본). 저장 시: U1과 같은 문서화된 예외(이 Mac의 로컬 파일, 디스크 암호화는 OS 설정) | 사진은 공개 거리뷰이지만 사람 얼굴과 번호판이 찍힐 수 있다. 별도 암호화는 구성하지 않고 로컬에만 둔다 |

| SECURITY-05 | 준수 | 명령줄 인자, 외부 응답과 이미지 검증(SEC3), 매개변수 바인딩 |
| SECURITY-09, 11, 15 | 준수 | 차단 시 즉시 멈춤(fail closed), 가려진 오류 메시지, 최상위 오류 처리 |
| SECURITY-10 | 준수 | 21개 전부 고정, CI `pip-audit`, 불필요한 의존성 제외, 공식 PyPI. SBOM은 배포가 없어 N/A |
| SECURITY-12 | 준수 | 키 없음 |
| SECURITY-13 | 준수 | 이미지를 검증하고 크기 한도를 둔다. 서드파티 라이브러리가 해석하는 내부 통신 응답은 라이브러리에 의존한다는 점을 위험으로 기록했다 |
