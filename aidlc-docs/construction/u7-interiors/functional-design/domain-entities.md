# U7 내부·성능 — Domain Entities

단계 3(2026-10-14). 질문과 답: `aidlc-docs/construction/plans/u7-interiors-functional-design-plan.md`(Q1~Q4 모두 A). 규칙 번호는 `business-rules.md`의 BR-I*.
모든 치수는 m(코드는 `layout.Item`으로 넘길 때 stud = m × 3.6). 박스의 로컬 좌표는 지금 그대로: u = 박스 긴 변(로컬 +X), v = 짧은 변(로컬 +Z), 면 f = −Z, b = +Z, l = −X, r = +X.

## 1. 입력 (지금 있는 것)

| 이름 | 어디서 | 내부가 쓰는 것 |
|---|---|---|
| `Body` | `layout_details.make_body`/`resolve_body` | `boxes`, `front`(앞 박스 번호), `facing.side`(도로 쪽 면), `floors` F, `fh`(층고), `height_m` H, `archetype`, `details`(`ground_use`, `rooftop`, `stair`), `roof_shape`, `usability`, `building_id` |
| 등급 | `tiers.tier_of(cfg, 칸)` | 1·2·3, 없으면 1 |
| 간판 단어 | `details_rules.pool_for` + `sign_name`(같은 slot) | 1층 가게 업종, 위층 간판이 있는 층의 업종 |
| 문 위치 | `layout_details._door_along(body)` | 현관 구멍 위치(앞면 along) |
| 수작업 건물 | `Manual`이 가진 `BuildingId` | 내부 없음 |

## 2. 새 개념

### Shell (껍데기)
건물의 박스마다 면 4개의 **벽 구간** 목록. 벽 구간 = (박스 번호, 면, along 시작, along 끝, y 아래, y 위). 형제 박스와 맞닿거나 형제 박스 안에 들어간 부분은 빠진다(BR-I3).

### Level (층)
k = 0 … F−1. 바닥 윗면 높이 `y_k`(BR-I5), 층 사이 판 두께 0.2. 맨 위층의 천장은 지붕(평지붕은 지금의 `#cap`, 경사 지붕은 천장판).

### Stairwell (계단실)
한 건물에 하나. (박스 번호, 모서리, 방향, 길이 L, 폭 2.2). 꺾음계단 한 단 = 층 k→k+1: 오르막 쐐기 A(폭 1.1, 높이 fh/2), 중간 참(2.2 × 1.1), 오르막 쐐기 B(되돌아옴). 위층 바닥에는 계단실 크기의 구멍.

### Core (엘리베이터)
아파트와 6층 이상 상가만. 계단실 옆 2.0 × 2.0 m 기둥 공간, 층마다 엘리베이터 문 부품 하나.

### Room / Kit (방과 꾸러미)
층마다 박스 하나 이상이 방이 된다(계단실·코어 자리를 뺀 직사각형). 꾸러미 = 방에 놓는 부품 목록(종류, 크기, 놓는 자리 규칙). 꾸러미는 (건물 유형, 층, 1층 용도, 업종, 등급)으로 정해진다(BR-I10).

### Trade (업종)
간판 단어 → 꾸러미 이름(BR-I11 표). 간판이 없는 층은 `pick`.

## 3. 새 항목 종류 (`layout.Item.kind`)

| kind | 무엇 | 충돌 | 그림자 | 재질·색 | 비고 |
|---|---|---|---|---|---|
| `wall` | 바깥 벽, 바닥판, 계단 쐐기·참, 현관 문틀, 옥상 계단탑, 엘리베이터 코어 벽 | 예 | 예(벽만), 나머지 아니오 | 벽: 건물 벽 색·재질. 바닥: `floor_*` 팔레트. 계단: `concrete` | 구조 |
| `interior` | 칸막이, 가구, 천장 등판, 엘리베이터 문, 주차선 | 가구·칸막이 예, 판·선 아니오 | 아니오 | 꾸러미 팔레트(BR-I12) | 꾸밈 |

- `building`(지금 박스)은 **부피**가 된다: 키 `hv=1`이면 Builder가 `Transparency=1`, `CanCollide/CanTouch/CanQuery=false`, 그림자 없음으로 만든다. 속성(`BuildingId`, `Floors`, `HeightBasis` …)은 그대로.
- 새 리터럴 키: `hv`(부피, 1), `px`(오르막 기울기, 도), `lt`(PointLight 반경 stud, 있으면 그 부품에 PointLight `Shadows=false`, `Brightness` 1.2, 따뜻한 흰색), `ef`(엘리베이터 문: 이 층 번호), `eF`(그 건물 층수). 엘리베이터 문에는 CollectionService 태그 `Elevator`.
- 칸 폴더: `Base`(Model, Persistent: 땅·도로·보행로·인도), `Buildings/<건물 ID>`(Model, Atomic), `Props`, `Spawn`. 종류별 개수는 칸 속성 `Made_<kind>`(verify가 읽음).
- 칸 폴더 아래에서 건물 하나의 모든 부품(외관·지붕·간판·내부)은 Model `<BuildingId>` 하나에 묶인다(스트리밍 단위, BR-I15).
- 매니페스트 `counts`에 `items_wall`, `items_interior`, `interior_buildings`, `interior_floors`, `stairwells`, `elevators`, `lights`가 더해진다.
