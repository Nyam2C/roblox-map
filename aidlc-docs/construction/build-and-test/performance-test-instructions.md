# Performance Test Instructions

부하 시험은 해당 없다(단일 사용자, 칸 단위 배치 실행). 대신 NFR-P1("칸 하나를 수 분 이내")을 실제 칸으로 잰다.

## 요구
- **칸 하나 수집·조립**: 수 분 이내(U1-NFR-P1).
- **DB 크기**: 3칸 규모에서 문제되지 않을 것.

## 측정 방법
```bash
time uv run --env-file .env src/cells.py --cells <칸ID>
time uv run --env-file .env src/register.py --cells <칸ID>
ls -la data/map.db
```
`collection_runs`의 `started_at`, `finished_at`으로도 볼 수 있다.

## U2 Studio 생성기 (2026-10-13, 첫 칸 `8930e0af13bffff`)

### 요구
- Python이 첫 칸의 덩어리 파일과 manifest를 쓰는 데 5초 이내. Studio 호출 한 번은 1초 이내(U2-NFR-P1, P2).
- 걸을 때 평균 60 FPS 이상, 순간 최저 30 FPS 이상, 1초 이상 끊기지 않을 것(U2-NFR-P4). 측정은 사용자 Mac의 Studio 플레이 테스트.

### 측정
| 항목 | 결과 | 요구 | 판정 |
|---|---|---|---|
| `build_luau.py` 전체(실행부터 끝까지) | 약 0.2초 (`plan_cell` 계산만 5 ms) | 5초 이내 | 통과 |
| 덩어리 파일 크기 | 5.4 / 6.6 / 6.6 / 2.0 KB | 10 KB 이하 | 통과 |
| 한 칸 재생성(부품 162개, Studio) | 3.6~5.6 ms | 호출당 1초 이내 | 통과 |
| 부품 수 | 163개(workspace 후손 527~539개, Studio 기본 물체 포함) | 칸당 1,000개 이하 | 통과 |
| 가만히 서 있을 때(맵 있음 / 없음) | 평균 60 FPS / 60 FPS, 30 FPS보다 느린 프레임 0 | - | 맵이 부하를 주지 않음 |
| 걷는 동안(창이 앞에 있을 때) | **평균 60 FPS, 30 FPS보다 느린 프레임 0**(26.5초, 1,591프레임) | 평균 60, 최저 30 | 통과 |
| 걷는 동안(창이 뒤에 있을 때) | 정확히 15 FPS 고정(프레임 438개 중 437개가 67 ms) | - | Studio의 백그라운드 프레임 제한 |

- **측정 주의**: Studio 창이 다른 앱 뒤에 있으면 Studio가 15 FPS로 제한된다. 같은 걷기에서 앞서 한 측정은 60 FPS였고 이번에는 15 FPS로 고정됐다(프레임 시간이 변하지 않고 66.7 ms에 붙어 있다). 이 제한이 걸린 값은 맵 성능이 아니다. 최종 확인(U5 끝, 칸 3개)은 Studio 창을 맨 앞에 두고 한다.
- 위 "가만히" 시험은 같은 자리에서 클라이언트에서만 `Auto`를 잠시 치웠다 되돌려 비교했다(서버는 그대로).
