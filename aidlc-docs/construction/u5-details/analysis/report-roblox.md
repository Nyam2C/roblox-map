## 1. Performance budgets (PC, walkable town)
- **No official part/instance threshold exists.** The docs' only numeric budget is a worked example: "stay below 1,000 draw calls and 1,000,000 triangles for the game to run well on your baseline device" and "At 60 FPS, the total budget for each frame is 16.67 ms" [DOC https://create.roblox.com/docs/performance-optimization/design].
- [DOC https://create.roblox.com/docs/performance-optimization/improve] Rendering section, verbatim: "A draw call is a set of instructions from the engine to the GPU to render something"; the engine will "collapse identical meshes with the same texture characteristics into a single draw call"; "Objects like decals, textures, and particles don't batch well and introduce additional draw calls"; "Handling shadows is an expensive process" and "Use the BasePart.CastShadow property to disable shadow casting on small parts"; "Placing objects with partial transparency near each other forces the engine to render the overlapping pixels multiple times"; FastCluster: "Too many parts in a Model could cause rebuilds more often due to the potential for a part's property to change". Texture memory: "a 1024x1024 pixel texture consumes four times the graphics memory of a 512x512 texture"; "Most minor images should be smaller than 256x256 pixels"; "Built-in materials use far less memory than custom textures" (design page).
- [DOC https://create.roblox.com/docs/reference/engine/classes/BasePart] `Transparency`: "partially transparent objects have some significant rendering costs"; "Having many translucent parts may impact performance"; avoid overlapping semi-transparent parts. `CastShadow` default true; "in complex scenes, strategically disabling it on certain parts can improve performance", but disabling can cause artifacts. `CanTouch=false` + `CanCollide=false` gives "a small performance gain".
- Part-count anecdotes [FORUM]: ~13k parts "typically don't create much of a performance impact" (https://devforum.roblox.com/t/too-many-parts-in-a-game/1284342, 2021); a 20,000-part house with "no noticeable lag" and an older PC lagging at ~30K-50K parts (https://devforum.roblox.com/t/how-optimized-are-parts/2618771, https://devforum.roblox.com/t/is-there-a-part-limit/755095); 10,000 anchored overlapping parts ran ~40 FPS GPU-bound because of z-fighting (coplanar faces), a 174k-triangle mesh scene held 60 FPS (https://devforum.roblox.com/t/parts-vs-meshes/398965). Staff on the old clustered renderer: "we can pack at most 72 parts into one batch on desktop (32 on mobile)" for dynamic clusters; any non-CFrame property change "rebake[s] the entire cluster" (https://devforum.roblox.com/t/thansparency-and-cframe-at-the-same-time-dont-mix-for-large-amounts-of-parts/12758) [STAFF, old].
- SurfaceGuis: appearance is cached and recomputed only when the GUI or a descendant changes [DOC SurfaceGui]. One Roblox ticket workaround set `MaxDistance=100` on every SurfaceGui, bringing the rendered glyph count to ~700; a lobby of sign boards lagged until TextLabels were consolidated [FORUM https://devforum.roblox.com/t/surfacegui-text-bugging-out-at-specific-camera-angles/3148740]. Rendered glyph count, not SurfaceGui count, is the lever.
- Glass: multiply blend; refraction only at high quality levels; "At Transparency 0, glass is completely opaque"; **"Non-opaque objects are currently not visible through glass"** (transparent parts, decals on transparent parts, particles, world-space GUI objects) — a deliberate perf trade-off [STAFF 2017 https://devforum.roblox.com/t/introducing-new-material-glass/64231]; still reported in 2025 ("glass is hiding surfaceguis", https://devforum.roblox.com/t/glass-material-issue/3924658) [FORUM]. Design consequence: no signs/SurfaceGuis behind Glass; shop fronts should be opaque dark SmoothPlastic with `Reflectance`, or Glass only where nothing is behind it.
- StreamingEnabled: no threshold is documented. Default on for new places, cannot be set from a script; `StreamingMinRadius` default 64, `StreamingTargetRadius` default 1024 studs; anchored assemblies stream per BasePart; benefits are join time, memory, frame rate [DOC https://create.roblox.com/docs/workspace/streaming]. Three H3-9 cells span roughly 2,000 × 2,000 studs, i.e. beyond the 1024-stud default target radius, so streaming would unload the far cell. With ~400 buildings × ~20-30 parts (≈10k parts) the anecdotal PC thresholds are not reached; streaming is optional for U5 and should be decided by a measurement at the end (CLAUDE.md "다음 할 일 2").

## 2. Repeating window patterns without parts
- `Texture` (inherits Decal): tiles its image; `StudsPerTileU/V` = tile size in studs, independent of part size, axes follow the part; `OffsetStudsU/V` shift; `Face`, `Color3` (tint, works only on white-ish images), `Transparency`, `ZIndex`; image via `Texture`/`ColorMapContent`; "a Texture needs an image asset" [DOC https://create.roblox.com/docs/reference/engine/classes/Texture]. Defaults [MEASURED]: `StudsPerTileU/V = 2`. `Decal` stretches one image over the face [DOC Decal]. Both "don't batch well and introduce additional draw calls" [DOC improve]: 400 buildings × 4 faces = 1,600 Texture instances ≈ 1,600 extra draw calls against the 1,000-draw-call docs example. Mitigations: only street-facing faces; or a `MaterialVariant` instead of per-face Textures (a material, so parts sharing it should batch like a built-in material — inference, not documented); or window strips as opaque parts (dark SmoothPlastic, `Reflectance` 0.2-0.4), 1 part per floor per face, which batch and need no asset.
- Asset requirement: `rbxassetid://<id>` from an upload. `rbxasset://` points to the local content folder [DOC https://create.roblox.com/docs/projects/assets]. Local inventory [MEASURED, `/Applications/RobloxStudio.app/Contents/Resources/content/textures`]: only `grid2.png` (128²), `grid4.png` (256²), `grid16.png` (512²) — opaque grey checker grids (viewed), `Blank.png`, `gradient.png`, `whiteCircle.png`, `SurfacesDefault.png`, `noise.dds`, `particles/*.dds`, `sky/*.dds`, `MaterialFramework/Grid.png`. **No brick/window/door texture ships locally**; the checker grids read as floor tiles, not windows.
- Upload paths: (a) Studio Asset Manager / Toolbox import; review "generally happens within a few hours"; a pending asset "cannot be seen" by users in a published place until approved [DOC projects/assets]. (b) Open Cloud `POST https://apis.roblox.com/assets/v1/assets`, multipart (`request` JSON with `assetType:"Decal"`, `fileContent`), `x-api-key` with `assets` Write scope, png/jpeg/bmp/tga < 8000×8000, ≤ 20 MB, poll `operations/{id}` until `done`, response carries `moderationResult.moderationState` (e.g. `MODERATION_STATE_APPROVED`) [DOC https://create.roblox.com/docs/cloud/guides/usage-assets]. (c) MCP `upload_image` [SCHEMA]: takes `imagePaths` that are **http(s) URLs** (example `http://localhost/image.png`), returns `{url: "rbxassetid://…"}`; a local PNG must be served (e.g. `python -m http.server`). `store_image` [SCHEMA] only converts a local png/jpg (≤ 5 MB) into an `IMAGEID_<id>` URI for `generate_procedural_model`'s reference image — not an rbxassetid. Whether a pending image is visible to its owner in Studio is not documented (forum claims only) [FORUM].
- `generate_texture` [SCHEMA]: "Re-textures an existing mesh using AI… Requires a source MeshPart or Model. Replaces the source in place." It does not take a Part face and returns no asset id → **not usable for `Texture.TextureId`**. `generate_material` [SCHEMA]: "Returns the BaseMaterial and Name of the generated MaterialVariant", params `materialPattern` (Regular|Organic), `materialId`, `baseMaterial` (enum includes Brick, Concrete, Plaster, CeramicTiles, ClayRoofTiles, RoofShingles…), `materialDescription`, optional `async`. This is the one generative tool that yields something a plain Part can use (`Material` + `MaterialVariant` name); it writes into `MaterialService` (a place mutation, so only in Build and Test).
- SurfaceGui grid for windows: possible but each is a world-space GUI (glyph/quad budget, MaxDistance), hidden behind Glass, and 1,600 of them is exactly the anecdotal failure case → not recommended for windows.

## 3. Signs (SurfaceGui + TextLabel, Korean)
- [MEASURED defaults from `Instance.new`] `SurfaceGui.SizingMode = FixedSize` with `CanvasSize = 800×600` (docs say the default is `PixelsPerStud` — set it explicitly), `PixelsPerStud = 50`, `LightInfluence = 0`, `MaxDistance = 0` (= unlimited; docs say 1000), `AlwaysOnTop = false`, `Brightness = 1`. Docs [https://create.roblox.com/docs/reference/engine/classes/SurfaceGui]: `AlwaysOnTop=true` renders over all 3D content and forces LightInfluence 0; `LightInfluence` 1 = lit by the scene (use 1 for daytime painted signs, 0 + `Brightness` for lit sign boxes); large `PixelsPerStud` on large faces hurts performance; `MaxDistance` for outdoor use should be set so the UI is small when it pops; only StarterGui/PlayerGui SurfaceGuis get input (irrelevant for static signs). At 3.6 studs/m a 3 m × 0.8 m sign = 10.8 × 2.9 studs = 540 × 144 px at 50 px/stud.
- Hangul rendering: Studio ships `content/fonts/families/NotoSansCJKFallback.json` (`"name":"NotoSansCJK Fallback"`, `"loadStrategy":"sameFamilyOnly"`, one Regular face `rbxassetid://123924484074402`) [MEASURED file]; no `Noto Sans KR` family exists. `TextService:GetTextBoundsAsync` for 3 Hangul chars at size 40 returned 75×40 for both `SourceSans` and `BuilderSans` (identical), vs 56 for "ABC" and 93 for 3 × U+FFFD tofu → Hangul is shaped by the shared fallback, not as tofu [MEASURED]. Consequences: the chosen `FontFace` only affects Latin/digits; Hangul always looks like Noto Sans CJK Regular (single weight; bold Hangul is not available). Default TextLabel font is `Enum.Font.Legacy` / `rbxasset://fonts/families/LegacyArial.json` [MEASURED]; `Enum.Font` has 53 items [MEASURED], `Font.fromName("BuilderSans")` builds `rbxasset://fonts/families/<name>.json` [DOC https://create.roblox.com/docs/reference/engine/datatypes/Font]. 43 family JSONs are installed locally (list in the content folder).
- Filtering: required only for "any displayed text that you don't have explicit control over" (TextBox input, external servers, data stores) [DOC https://create.roblox.com/docs/ui/text-filtering]; developer-authored fictional sign names need no filtering. No documented `TextLabel.Text` length limit.
- Project constraint: Korean cannot pass `SAFE_TEXT` (`src/build_luau.py:36`). Workable encoding that stays inside `[A-Za-z0-9:#_.-]`: codepoints as hex joined by `.` (e.g. `C2EC.C6D0.ACE0`) decoded in Builder.luau with `utf8.char(tonumber(h,16))`; also keeps the determinism/property tests simple.
- Neon/SmoothPlastic part + SurfaceGui: fine; Neon "appear[s] to glow" and Bloom amplifies it [DOC parts]. A SurfaceGui still must sit on a BasePart face (or `Adornee`); `ZOffset` layers GUIs on the same face.

## 4. Roofs — WedgePart / CornerWedgePart conventions [MEASURED by `GetClosestPointOnSurface` probe on Size (4,4,4), docs give no geometry]
- **WedgePart**: the vertical rectangular face is **Back (+Z)**; the slope descends from the Back-top edge to the **Front (−Z) bottom edge** (thin edge at −Z); triangular faces are **Left/Right (±X)**; `Size.Y` = rise, `Size.Z` = run. (Probe: top corners at +Z on surface, d=0; at −Z d=2.83; Front mid d=1.41.)
- **CornerWedgePart**: single apex at **(+X, +Y, −Z)**; vertical triangular faces are **Front (−Z) and Right (+X)**; the two sloped faces descend toward **−X and +Z**, meeting on a fold from the apex to the bottom corner (−X, −Y, +Z). Docs only say "a corner piece which has the same properties as a Part" and "slopes on two perpendicular faces".
- Recipes (footprint Lx along X, Wz along Z, wall top y0, rise H): **shed** = 1 WedgePart Size (Lx, H, Wz), +Z toward the high wall. **Gable** (ridge along X) = 2 WedgeParts Size (Lx, H, Wz/2), A at z=−Wz/4 yaw 0, B at z=+Wz/4 yaw 180°; the gable triangles are the wedges' ±X faces, so **no separate triangular wall part is needed**. **Hip** = 2 WedgeParts Size (Lx−Wz, H, Wz/2) + **4** CornerWedgeParts Size (Wz/2, H, Wz/2) (one per side per end, apex corner on the ridge end); the task's "2 wedges + 2 corner wedges" is one corner wedge short per end. **Pyramid** (square) = 4 CornerWedgeParts with apexes at the centre. **Eave overhang o**: keep pitch, use Size (Lx+2o, H·(Wz/2+o)/(Wz/2), Wz/2+o) centred at z=∓(Wz/4+o/2), y = y0 + H − H'/2 (ridge stays at y0+H); the part dips below the wall top inside the walls, hidden. **Flat roof + parapet**: 4 thin parts (2 full-length + 2 between them, no coplanar overlap) — Unions need `RenderFidelity`/`TriangleCount`, hide children, and are "heavily unoptimized" per forum [FORUM]; docs give no union batching statement. Avoid coplanar faces between roof and wall tops (z-fighting case in §1).

## 5. Materials
- `Enum.Material` in this Studio [MEASURED]: Plastic, SmoothPlastic, Neon, Wood, WoodPlanks, Marble, Basalt, Slate, CrackedLava, Concrete, Limestone, Granite, Pavement, Brick, Pebble, Cobblestone, Rock, Sandstone, CorrodedMetal, DiamondPlate, Foil, Metal, Grass, LeafyGrass, Sand, Fabric, Snow, Mud, Ground, Asphalt, Salt, Ice, Glacier, Glass, ForceField, Air, Water, Cardboard, Carpet, CeramicTiles, ClayRoofTiles, RoofShingles, Leather, Plaster, Rubber (45; Air/Water are terrain). Same list on the enum page and on https://create.roblox.com/docs/parts/materials [DOC]; `generate_material.baseMaterial` enum matches [SCHEMA]. Pre-2022 textures are listed only as asset-ID tables; no toggle is documented.
- `MaterialVariant` [DOC https://create.roblox.com/docs/reference/engine/classes/MaterialVariant]: only works under `MaterialService`; a variant named like a base material overrides it globally, otherwise set `BasePart.MaterialVariant` (string) per part; `ColorMap`/`NormalMap`/`MetalnessMap`/`RoughnessMap` are ContentIds (uploads), `StudsPerTile` scales tiling (default **10** [MEASURED]), `MaterialPattern` Regular|Organic. Metalness has no effect when `EnvironmentSpecularScale = 0`. Physical props priority: part > custom material > override > base.
- Scale: built-in material tile size per stud is **not documented**; measure in Studio (brick courses per stud) before choosing. With 1 stud = 0.278 m, a real brick course (~0.065 m) ≈ 0.23 stud; `Texture.StudsPerTile` default 2 = 0.56 m, `MaterialVariant.StudsPerTile` default 10 = 2.8 m.

## 6. Street assets, Creator Store, MCP tools
- `search_asset` [SCHEMA]: scopes auto/creator_store/user/group/universe; `query` with `+` and quotes; `assetType` (Model, Audio, Mesh, MeshPart, Image, Decal, Video, Package); `priceFilter free|paid|all`, `verifiedCreatorsOnly`, `tags`, `facets`, `maxResults` 1-20; returns name, type, source, price, `creatorId/creatorName`, `thumbnailUrl`, plus `context` (userId, universeId, isPublished…). Creator Store results "may occasionally be restricted". `insert_asset` [SCHEMA]: numeric `assetId`, optional `assetName`, `assetType` hint, `parentPath` (default workspace); supports Model/Package/Mesh/MeshPart/Image/Decal/Audio/Video/Animation — it mutates the place.
- Licensing [DOC https://create.roblox.com/docs/production/creator-store]: free assets can be saved "so that you can reuse the assets in any of your projects"; Open Use dependencies may be redistributed in composites, Restricted ones not; nothing about attribution. Private place use is covered. Safety [DOC https://create.roblox.com/docs/scripting/security/third-party-vulnerabilities]: Toolbox marks models containing scripts; moderation "is not guaranteed to remove all such scripts"; recommended sandboxing (`Workspace.SandboxedInstance=Experimental`, model `Sandboxed=true`, minimal Capabilities). Design rule: strip all `Script`/`ModuleScript` from inserted props, or only insert script-free models.
- `generate_mesh` [SCHEMA]: AI textured mesh from `textPrompt`, `maxTriangles` 12-20000, `size {x,y,z}` bounding box, `segmentation` auto|none|explicit (`partNames` ≤ 8), `async`. `generate_procedural_model` [SCHEMA]: builds a ProceduralModel from blocks/spheres/cylinders/wedges with editable attributes, optional reference image via `store_image`, **auto-inserts into workspace** (mutation; would need moving into `Workspace/Manual`). `segment_mesh` [SCHEMA]: splits a MeshPart/Model into ≤ 5 named parts as a sibling Model. `skill` [SCHEMA] offers `rbx-perf-profiling` (MicroProfiler via LibMP) and `rbx-scene-analysis` (SceneAnalysisService) — useful for the FPS gate. `subagent` [SCHEMA] types: explore, screen_capture, unit_test.
- Part-built fallbacks are plain `Part`s with `Shape` Ball/Cylinder/Block/Wedge/CornerWedge [DOC parts]: tree = Cylinder trunk + 2-3 Ball crowns (Grass/LeafyGrass material), pole = Cylinder + Block crossarm, lamp = Cylinder + small Neon Block (+ optional `PointLight`, range cap 60 studs [FORUM]), crosswalk = thin white SmoothPlastic strips on the road, bus stop = 3 Blocks + Glass-free roof, traffic light = Block + 3 Neon Balls. All instance-free, batchable, deterministic.

## 7. Instancing
- [DOC improve] identical meshes "with the same texture characteristics" collapse into one draw call; a Humanoid-bearing Model becomes one FastCluster; too many parts per Model → more rebuilds. [STAFF 2017 https://devforum.roblox.com/t/rendering-updates-september-2017/54148] instancing batches the same archetype — "same MeshPart mesh, same CSG render data, and eventually same shape of a basic part" — with size/cframe/color fetched from a per-instance buffer; at the time only MeshParts/CSG, basic parts "will take a while"; a later update on basic-part instancing was not found (forum opinions conflict) [FORUM]. [FORUM] `TextureId`/`MeshId` differences break mesh instancing; color does not.
- Practical reading: thousands of identical-shape, same-material anchored Parts are the cheapest primitive; MeshParts with one shared MeshId (e.g. one tree mesh) cost one mesh in GPU memory and batch per mesh+texture. Folder vs Model: no documented render difference for static anchored parts; Model matters for streaming mode (`ModelStreamingMode` Atomic/Persistent) and for the `BuildingId` override in `Workspace/Manual`.

## 8. Lighting
- **Unified Lighting is live** (beta 2025-01-21, fully released 2025-07-23, Roblox Rendering Team) [STAFF https://devforum.roblox.com/t/let-there-be-unified-light-unified-lighting-is-fully-live/3401512]: `Technology` is deprecated and replaced by `LightingStyle` (Realistic | Soft) + `PrioritizeLightingQuality`. Mapping: Future → Realistic + Enabled; ShadowMap → Soft + Enabled; Voxel → Soft + Disabled. "performance will not degrade, and in certain scenarios, we've seen improved performance for the same perceptible visual quality". Enum docs: Realistic = "The most advanced and realistic lighting and shadows Roblox can deliver", Soft = "A flat, retro-Roblox look" [DOC LightingStyle]. The place is currently Soft + Enabled (= ShadowMap); for the user's goal switch to **Realistic + Enabled** (non-scriptable, set in Studio Properties — a place change).
- [FORUM https://devforum.roblox.com/t/future-vs-shadowmap/658587] sun-only outdoor scenes look nearly the same under ShadowMap and Future; Future matters for PointLight/SpotLight shadows (night-time lamps/signs). [DOC Lighting] `GlobalShadows` voxels are 4×4×4 studs (objects smaller than that cast poor shadows); `EnvironmentDiffuseScale/SpecularScale` default 0 (place already 1), `ShadowSoftness` 0.2, `ExposureCompensation` −5..5.
- Atmosphere (`Density`, `Offset`, `Haze`, `Color`, `Glare`, `Decay`), Bloom, ColorCorrection, SunRays, DepthOfField, ColorGrading (`TonemapperPreset` Default|Retro): no cost figures in docs; "some effects may not appear" below the Studio Editor Quality Level [DOC https://create.roblox.com/docs/environment/post-processing-effects, https://create.roblox.com/docs/environment/atmosphere]. DepthOfField blurs distant streets while walking — likely disable for a town.

## 9. Overhead wires: Beam
- [DOC https://create.roblox.com/docs/reference/engine/classes/Beam] "A Beam object connects two Attachments by drawing a texture between them"; "If this property [Texture] is not set, the beam will be displayed as a solid line" coloured by `Color`; `Segments` default 10 [MEASURED]; `Width0/1` default 1 stud [MEASURED]; `CurveSize0/1` bend the Bézier (sag); `FaceCamera` needed because "A Beam is a 2D projection… may not be visible from every angle"; `LightInfluence` 0 = unlit (default 0 [MEASURED]); `LightEmission` does not light the scene. Attachments must be on BaseParts (the poles). SpecialMesh is irrelevant for wires.
- Cost [FORUM]: "a single beam on its own is typically equal to or lower than the memory usage of a part", and there is an undocumented on-screen beam cap that scales with graphics quality (https://devforum.roblox.com/t/do-beams-create-lag/675990, https://devforum.roblox.com/t/electric-arcs-effect/228413); a 65-beams-updated-per-frame spike report is irrelevant for static wires. Fallback: one thin Cylinder Part per span (batches, no sag).

## 10. Design implications (summary)
1. Keep everything as plain anchored Parts/Wedges/CornerWedges with built-in materials; it is the only primitive whose cost is predictable without uploads or moderation.
2. Windows: opaque dark window-strip parts or one `MaterialVariant` (from `generate_material`, Build and Test only) — avoid 1,600 per-face Textures and avoid Glass where SurfaceGuis or transparent parts are behind.
3. Signs: SurfaceGui with explicit `SizingMode=PixelsPerStud`, `PixelsPerStud=50`, `LightInfluence=1` (day) / 0 (lit), `MaxDistance≈300`, `AlwaysOnTop=false`; Korean via hex-codepoint encoding decoded with `utf8.char`; Hangul always renders in the single Noto CJK fallback face.
4. Roof axis facts in §4 are measured, not documented; encode them once in `layout.py` and cover with Hypothesis (apex/ridge coincidence, no coplanar faces).
5. `CastShadow=false` on small parts (signs, window strips, wires, lamp heads); `CanTouch=false, CanQuery=false` on props.
6. Set `LightingStyle=Realistic`, consider disabling DepthOfField; measure FPS with Studio in front (CLAUDE.md), optionally with the MCP `rbx-perf-profiling` skill; enable `StreamingEnabled` only if the 3-cell measurement needs it.
