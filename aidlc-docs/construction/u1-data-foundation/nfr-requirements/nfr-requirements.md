# U1 데이터 기반 — NFR Requirements

근거: 계획서 답변 Q1~Q7, 기본값 N-1~N-9, 요구사항 NFR-1~9, U1 Functional Design.
실행 환경은 사용자 Mac에서 `uv run`으로 돌리는 Python 스크립트와 SQLite 파일 하나다. 서버, 클라우드, 사용자 인증은 없다.

## 1. 확장성
- **U1-NFR-S1** 가까운 시일의 규모는 심원고 3칸이다(Q6=A). 칸 단위로 독립 처리하므로 칸이 늘어도 구조는 그대로 간다.
- **U1-NFR-S2** DB는 SQLite 파일 하나다. 3칸 규모(건물 수십~수백 개)에서는 크기와 속도가 문제되지 않는다. 동네 단위로 확장할 때 다시 평가한다.

## 2. 성능
- **U1-NFR-P1** 칸 하나를 수집하고 조립하는 데 수 분 이내가 목표다(N-6). 시간의 대부분은 외부 API 응답과 호출 간격이다.
- **U1-NFR-P2** V-World는 한 번에 1000건까지 주고(`page`로 넘김) 칸 하나에 버퍼를 포함해 수백~1000건 이상이 나오므로 `total`만큼 페이지를 끝까지 받는다. 호출 사이에 간격을 둔다. Overpass 호출 사이에도 지금처럼 간격을 둔다(공개 서버에 대한 예의).
- **U1-NFR-P3** 겹침 계산은 건물 수가 수십~수백 개라 쌍별 비교로 충분하다. 공간 인덱스는 쓰지 않는다. 칸당 건물이 수천 개로 늘면 그때 도입한다.

## 3. 가용성과 복구
- **U1-NFR-A1** 복구 목표는 RTO/RPO 수 시간, 백업 후 복구다(NFR-6).
- **U1-NFR-A2** U1의 데이터(`osm_buildings`, `gis_buildings`, `buildings`, `street_features`)는 원천에서 다시 받을 수 있다. 복구는 DB 파일을 지우고 S1을 다시 돌리는 것이다.
- **U1-NFR-A3** 재생성이 안 되는 값(`overrides`, 사진)은 U1이 아니라 U4, U3의 몫이다. U1은 재수집이 `overrides`와 `estimates`를 건드리지 않는 것만 보장한다(BR-6.2).

## 4. 보안
- **U1-NFR-SEC1 비밀값** V-World 인증키는 환경변수 `VWORLD_KEY`로만 받는다(데이터 포털 키 `DATA_GO_KR_KEY`는 U1에서 쓰지 않지만 `.env`에 보관한다). `.env`는 git에서 제외한다. 로그, 오류 메시지, 실행 기록에 키를 넣지 않는다. 키가 들어간 요청 URL을 로그에 남길 때는 키 부분을 가린다.
- **U1-NFR-SEC2 입력 검증** 명령줄 인자(해상도, 좌표, 칸 ID)는 형식과 범위를 검사한다. 칸 ID는 H3 유효성을 확인한다. 외부 응답은 쓰기 전에 검증한다(BR-7.4).
- **U1-NFR-SEC3 질의 안전** SQLite 질의는 매개변수 바인딩만 쓰고 문자열을 이어 붙이지 않는다. 외래 키 제약을 켠다.
- **U1-NFR-SEC4 전송 보안** 모든 외부 호출은 HTTPS이고 인증서 검증을 끄지 않는다.
- **U1-NFR-SEC5 안전한 역직렬화** 외부 데이터는 JSON으로만 읽는다. `pickle` 등 코드를 실행할 수 있는 형식은 쓰지 않는다.
- **U1-NFR-SEC6 오류 처리** 각 스크립트의 진입점에 최상위 오류 처리를 둔다. 오류가 나면 작업을 멈추고 로그에 남기고 0이 아닌 종료 코드로 끝낸다. 칸 단위 쓰기는 트랜잭션이라 중간에 실패하면 되돌린다(BR-7.1). 메시지에 키나 내부 경로를 넣지 않는다.
- **U1-NFR-SEC7 공급망** 의존성은 정확한 버전으로 고정한다(Q4=A). 취약점은 `pip-audit`를 수동으로 돌려 점검하고 절차를 문서에 적는다. 쓰지 않는 의존성은 두지 않는다. 패키지는 공식 PyPI에서만 받는다.

## 5. 신뢰성
- **U1-NFR-R1** Overpass는 429, 502, 504일 때 10초, 30초, 60초 간격으로 재시도한다(BR-7.3).
- **U1-NFR-R2** 칸 단위로 필수 원천(V-World 건물통합정보, OSM)이 모두 성공해야 저장한다(BR-7.1).
- **U1-NFR-R3** 모든 실행은 `collection_runs`에 시작, 종료, 상태, 건수, 실패 이유를 기록한다.
- **U1-NFR-R4 로그(Q5=A)** 표준 `logging`으로 콘솔에 출력하고 `data/logs/`에 파일로도 저장한다(git 제외). 각 줄에 시각, 수준, 칸 ID, 메시지가 있다. 로그 파일은 자동 삭제하지 않고 필요하면 수동으로 지운다.
- **U1-NFR-R5 GIS 접근 불가** GIS건물통합정보에 접근할 수 없으면 OSM만으로 조립한다(BR-4.10, 설계 F-8). Q7=B(미신청)였으나 이후 사용자가 V-World 개발키를 발급받았다(발급 2026-10-13, 만료 2027-04-13, 연장 최대 3회). 2026-10-13 시험 호출로 V-World가 건물 외곽선과 층수·높이를 주는 것을 확인했다(건물통합정보 레이어 `LT_C_BLDGINFO`). 따라서 데이터 포털의 GIS건물통합정보 활용신청은 필요 없다.

## 6. 유지보수성과 테스트
- **U1-NFR-M1 테스트 도구(Q2=A, PBT-09)** `pytest`와 `Hypothesis`를 쓴다. 테스트는 `tests/`에 두고 실패 시 Hypothesis가 시드와 최소 반례를 출력한다(PBT-08).
- **U1-NFR-M2 테스트 범위** U1 Functional Design의 속성 P-1~P-9를 속성 기반 테스트로 만든다. 외부 API 호출은 예시 기반 테스트에서 저장해 둔 응답 샘플로 확인한다. 도메인 생성기(건물 외곽선, 칸 안의 좌표, OSM 태그 문자열)는 `tests/`의 공용 모듈에 한 번만 정의한다(PBT-07).
- **U1-NFR-M3 순수 로직 분리** 좌표와 외곽선 계산, 정규화, 건물 조립은 입출력이 없는 순수 함수로 만든다. 공용 순수 함수는 `src/geo.py`에 두고 C1, C2가 가져다 쓴다(N-9). `db.py`는 DB 접근만 한다.
- **U1-NFR-M4 테스트 실행** 테스트는 `uv run --with-requirements tests/requirements.txt pytest tests/`로 돌린다. `tests/requirements.txt`는 `pytest`, `hypothesis`, `shapely`, `h3`를 `==`로 고정하고, 스크립트의 인라인 의존성과 같은 버전을 쓴다. 두 곳의 버전이 어긋나면 알려 주는 테스트 하나를 둔다(N-8).
- **U1-NFR-M5** 코드 스타일 도구(포매터, 린터)는 이번에 요구하지 않는다.

## 7. 사용성
- **U1-NFR-U1** 인터페이스는 명령줄뿐이다. 진행 상황(칸 ID, 단계, 건수)과 실패 이유가 콘솔에 한눈에 보이게 한다. 접근성 요구는 없다.

## 8. 외부 연동
- **U1-NFR-X1** Overpass(공개 서버)와 V-World 데이터 API(`api.vworld.kr/req/data`, 개발키, 시험 호출 성공, `domain` 파라미터 없이 호출됨, 한 번에 최대 1000건).
- **U1-NFR-X2** V-World의 높이(`height`)는 45~62%의 건물에만 값이 있고 0이나 빈 값은 없음으로 본다(BR-5.3). 층수는 88~93%에 값이 있다. 건축HUB API는 호출만 확인했고 U1에서는 쓰지 않는다(키는 `.env`에 보관).
