# U5 디테일 — Functional Design Plan

대상 컴포넌트: C6 확장(`src/layout.py`, `src/build_luau.py`, `studio/Builder.luau`, 새 순수 모듈 `src/details.py`, 필요하면 `details` 판단 명령). 요구사항: FR-4(지붕, 층 구분, 창문·문, 간판, 대표 건물 수작업), FR-5(일반 재질·텍스처), FR-6(간판·상호는 전부 가상), FR-7(주거 건물도 같은 수준), FR-3(가로시설, U2에서 미룬 부분), NFR-1(3칸에서 끊김 없이), NFR-3(같은 입력 같은 결과), NFR-4(사진은 로컬에만), NFR-8(속성 기반 테스트). 이전 결정: 형태는 데이터로, 거리뷰는 외관 판단용(사진을 텍스처로 쓰지 않는다), 기하는 전부 Python이고 `Builder.luau`는 부품만 만든다(U2 BR-7.5), `Manual`이 `BuildingId`로 이긴다(U2 BR-2.8), 최종값은 보정 > 사진 판단 > 대장 > 기본값(U4), Luau 코드에 들어가는 글자는 `[A-Za-z0-9:#_.-]`뿐(U2 SEC2).

### 코드 확장점 (상세는 `analysis/report-code.md`)

- `layout.Item`(kind, name, group, seq, 위치·크기·yaw, material, color, attrs) → `item_literal`(키 `k n x y z w h d r`, 건물 `s e q f b a c v`) → `Builder.add`(kind마다 폴더, `Manual`의 `BuildingId`면 건너뜀) → `verify`(폴더별 개수 = manifest `items_<kind>` + 건너뛴 수). 새 kind는 `LOOKS`·`ORDER`·`FOLDER_OF`에 한 줄씩이면 정렬·manifest·verify가 공짜다.
- 덩어리 여유: chunk-002/003이 9.0 KB로 10 KB 경고선에 20 B/건물 남았다. 항목이 늘면 `chunk_size`와 경고선을 같이 정해야 한다.
- 최종값 `EffectiveBuilding`에 `roof_shape`가 있지만 아직 Luau로 안 보낸다. `estimates.note`는 자유 문장이라 코드에 못 넣지만 규칙의 신호로는 읽을 수 있다(위 어휘 수).
- 지키는 것: BR-6.4(같은 입력 같은 글자), BR-7.5(기하는 Python), SEC2(`SAFE_TEXT`), `Builder.luau`의 `:Destroy()` 1개, `require` 캐시(모듈 교체는 Clone 후 Destroy).
