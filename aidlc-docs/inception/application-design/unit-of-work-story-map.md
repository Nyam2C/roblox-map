# 요구사항 ↔ 유닛 매핑

User Stories를 건너뛰었으므로 스토리 대신 요구사항(FR, NFR)을 유닛에 배정한다. 모든 항목이 어느 유닛엔가 배정돼 있다.

## 기능 요구사항

| 요구사항 | 내용 | 유닛 |
|---|---|---|
| FR-1 | 구역 → H3 칸 | U1 |
| FR-2 | OSM 건물 수집, 건축물대장 속성 연결 | U1 |
| FR-3 | 도로·인도·가로시설 | U1 (수집), U2 (생성) |
| FR-4 | 건물 박스, 지붕, 층 구분, 창문·문, 간판, 본관 수작업 | U2 (박스), U5 (나머지) |
| FR-5 | 일반 재질과 텍스처로 현실감 | U2 (기본 재질), U5 (텍스처) |
| FR-6 | 가상 간판·상호 | U5 |
| FR-7 | 주거 건물도 동일 수준 재현 | U5 |
| FR-8 | 거리뷰 360도 캡처, 높이·외관 판단 | U3 (캡처), U4 (판단) |
| FR-9 | 층수는 대장 1순위, 사진 검증, 없거나 어긋나면 추정, 같이 확인해서 보정, 근거 기록 | U1 (대장 확보), U4 (판정과 보정) |
| FR-10 | 칸 1개를 1:1로 만들어 스케일 결정 | U2 |
| FR-11 | 자동·수작업 레이어 분리, 재생성해도 수작업 보존 | U2 (Studio 레이어), U4 (보정 데이터 보존) |
| FR-12 | Studio MCP로 생성 | U2 |
| FR-13 | 맵을 걸어 다니며 구경, 정문 앞 도로 스폰 | U2 |

## 비기능 요구사항

| 요구사항 | 내용 | 유닛 |
|---|---|---|
| NFR-1 | 3칸 규모에서 끊김 없이 걸어 다닌다 | U2 (첫 확인), U5 (3칸 최종 확인) |
| NFR-2 | 건물 위치 정확도 수 m 이내 | U1 (데이터 한계 기록), U2 (변환 정확도) |
| NFR-3 | 같은 입력이면 같은 결과, 칸 단위 재실행 | 전 유닛 |
| NFR-4 | 거리뷰 이미지는 로컬에만, 텍스처는 일반 이미지만 | U3, U5 |
| NFR-5 | 속도 제한, 차단 시 우회 없이 중단 | U3 |
| NFR-6 | 복구: 맵은 클라우드 저장과 `.rbxl` 복사본, 보정은 git | U4 (보정 내보내기·복구), 서비스 S5 |
| NFR-7 | 키는 환경변수, 의존성 고정, 외부 응답 검증 | 전 유닛 (U1에서 먼저 정함) |
| NFR-8 | 순수 함수는 속성 기반 테스트 | 순수 로직이 있는 유닛 (U1, U2, U3, U4, U5) |
| NFR-9 | git은 스크립트와 문서, `.rbxl`·`data/`·`captures/`·`.env` 제외 | U1 (`.gitignore`에 `data/` 추가) |

## 확인
- FR-1~13 모두 배정됨
- NFR-1~9 모두 배정됨
- 어느 요구사항도 유닛 밖에 남지 않았다
